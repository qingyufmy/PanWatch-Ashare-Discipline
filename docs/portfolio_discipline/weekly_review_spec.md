# 周报与迭代规范

每日收集：冻结 Eval Case、Issue 签名聚类、分钟线新鲜度、信号/人工执行/未执行及止损纪律。周五 20:30 的全持仓 DEEP 仅作为审阅证据；21:20 的 P10_REVIEW 形成系统周报，不自动生成或激活新 Prompt。双周用冻结案例与后续自然日 Shadow 对比 Champion/Challenger；月末复评模型延迟与 Schema、数据源质量、阈值、依赖版本。候选变更必须记录原因、影响案例、回放和回归结果。

周报至少包括：持仓及可卖数覆盖、计划与执行差异、未执行和下一交易日待办、ADD/REDUCE/EXIT 的后续结果（如可核实）、收益与回撤（仅在可核实资产序列足够时计算）、模型 FAST/DEEP 次数与延迟、Schema 失败、分钟线缺口、Issue 趋势、关键槽缺失、EOD 对账、Prompt 候选与 Shadow 差异、PanWatch/TradingAgents/模型服务与依赖变化。无可靠样本则填“未验证”，不能写 0 或 100%。

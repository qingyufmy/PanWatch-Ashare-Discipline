# 价格事实、账户范围和开盘批次修复

## 背景

冻结的历史输入确认：部分模型理由把高于观察价写成低于观察价，旧门禁只校验输出结构；模拟持仓上下文导致已在模拟盘清仓的股票影响用户声明持仓建议；首次常规盘中批次距离开盘存在空档。部分风险通知只含代码。

## 变更内容

- `declared-facts-v1` 使用 Decimal 计算 ABOVE / AT_OR_BELOW / UNKNOWN；逐股记录 decision_basis、原模型提案、冻结比较事实与完整政策。错误比较、错误账户范围和触价后 HOLD/ADD 均拦截，Issue 留痕。
- 专用 `intraday_review` Prompt 1.0.4-declared-facts 与每日复盘 Prompt 分离；用户声明持仓决定建议输入。模型输入移除模拟现金和模拟持仓，显式标记 USER_DECLARED。现金未核实的加仓仅能给条件提案，真实批准仍由原政策和用户确认控制。
- PAPER_ONLY 必须验证新事实合同及十三条真实规则 ID；模拟数量、T+1、整手、行情、账户现金和仓位上限继续独立检查。模拟账户不足以执行声明数量时跳过并记录原因，不擅自改变实盘声明数量。
- 被拒绝的新批次决议覆盖旧建议，页面显示待核查，不再显示旧的明确买卖标签。独立且已确认的硬风险仍优先展示。
- 开盘增加 09:30、09:35、09:40 全持仓批次，随后沿用原批次；每轮一次模型请求。与 09:25 竞价证据、60 秒硬风险和每分钟模拟扫描配合。报价未更新或模型超过时效时不得成交。新时段只从激活时刻起核查漏跑。
- 新飞书消息统一显示股票名称和代码，含单票风险与批量正文；查不到名称则明确待核实。历史消息、原内容 hash、去重键和发送状态保留。候选通知仍 SUPPRESSED。
- 模拟运行状态支持展示历史表现完整性说明；旧错误成交保留，累计收益不能作为修复后策略有效性的纯净样本。

## 验证

相关回归测试、前端生产构建和运行验证结果见本目录 deployment_acceptance.md。冻结的历史模型输出识别三条反向价格比较；独立数据库的一次全持仓模型调用覆盖完整组合并通过比较事实检查。该验证无实盘、无模拟填单、无通知、无历史信号回填。条件加仓的现金措辞调整后复用相同结构和数值用例，不额外消耗模型调用。

## 边界与后续

本次为本地修复部署与候选分支交付，不代表自然交易日或 P10 的 PROD 验收。新开盘批次需以自然产生的完成时间、行情来源时间、合同字段、政策和模拟扫描结果验收。没有证券来源核实和券商账本时不得宣布实盘批准。历史受影响模拟成交不反向修改，不重置账户，不重发旧通知。
